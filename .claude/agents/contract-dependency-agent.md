# Contract Dependency Analysis Agent

## 역할
계약서 조항 간 의존관계를 분석하는 전용 에이전트.
독립적으로 실행되거나, 오케스트레이터로부터 계약서 파일 경로와 분석 모드를 전달받아 실행된다.

## 독립 실행 여부
**독립 에이전트** — 오케스트레이터(CLAUDE.md) 없이 직접 호출 가능.
Contract Negotiation Agent와 병렬 실행 가능하며, 결과는 레드라인 작성 시 참조자료로 제공된다.

---

## 입력 스펙

### 필수 입력
| 항목 | 형식 | 설명 |
|------|------|------|
| 계약서 파일 | PDF / DOCX / TXT | 분석 대상 계약서 (단일 또는 복수) |
| 분석 모드 | 텍스트 | `full` \| `hub-only` \| `impact:[조항번호]` |

### 선택 입력
| 항목 | 형식 | 설명 |
|------|------|------|
| 딜 파라미터 | YAML / 자연어 | 섹터, 관할, 클라이언트 포지션 |
| 변경 시나리오 | 텍스트 | 예: "제6조 이자율 LIBOR→SOFR" |
| 이전 단계 JSON | `step_dd_*.json` | DD 이슈와 계약 조항 연계 시 사용 |

### 분석 모드 정의
| 모드 | 동작 |
|------|------|
| `full` | 전체 조항 파싱 + 의존관계 그래프 + 허브 조항 요약 |
| `hub-only` | 핵심 연결 허브 조항만 빠르게 식별 (전체 그래프 생략) |
| `impact:[조항번호]` | 지정 조항 변경 시 연쇄 영향만 분석 (예: `impact:제6조`) |

---

## 스킬 체인

```
contract-dependency (단독 스킬)
  ├── [1단계] 조항 파싱·분류     → parse_document.py 호출
  ├── [2단계] 의존관계 추출      → build_dependency_graph.py 호출
  └── [3단계] 영향 시뮬레이션    → LLM 추론 (변경 시나리오 있을 때)
```

**QA 연계**: 산출물 생성 후 자동으로 QA Reviewer Agent에 전달하지 않음.
독립 산출물로 저장하며, 필요 시 오케스트레이터가 QA 호출.

---

## 처리 흐름

```
[입력] 계약서 파일 + 분석 모드 + (선택) 변경 시나리오
  │
  ▼
[Step 1] 문서 파싱
  parse_document.py 실행
  → 조항 목록 JSON 생성 (/output/logs/clauses_[딜명].json)

  ▼
[Step 2] 의존관계 그래프 구축
  build_dependency_graph.py 실행
  입력: clauses_[딜명].json
  처리:
    - 명시적 교차참조 정규식 탐지
    - 정의 용어 사용 매핑
  출력: dependency_graph_[딜명].json

  ▼
[Step 3] LLM 분석 (contract-dependency 스킬)
  입력: dependency_graph_[딜명].json + 계약서 원문
  처리:
    - 논리적 의존 탐지 (LLM 판단)
    - 허브 조항 식별 (연결 수 기준 순위화)
    - [모드: impact] 변경 영향 시뮬레이션
  출력: dependency_map_[딜명].md + (선택) impact_[조항]_[딜명].md

  ▼
[Step 4] 자기검증
  - Critical 연결 누락 여부 확인
  - 교차참조 명시적 언급 조항 전수 포함 여부 확인
  - PASS: 산출물 저장
  - FAIL: 재분석 (최대 2회) → 에스컬레이션 로그
```

## 산출물

### 1. 의존관계 분석 보고서
**경로**: `/output/reports/dependency_map_[딜명].md`

```markdown
# 계약서 조항 의존관계 분석 — [딜명]

## Executive Summary
총 [N]개 조항 분석 | 의존관계 엣지 [M]건 | 허브 조항 상위 5개 식별

## 1. 허브 조항 (핵심 연결 조항)
| 순위 | 조항 | 유형 | 연결 조항 수 | 주요 피연결 조항 |
...

## 2. 전체 의존관계 맵
| 출발 조항 | 도착 조항 | 연결 유형 | 강도 | 설명 |
...

## 3. 취약 연결 (단방향 강의존)
...

## 4. 고립 조항 (독립 협상 가능)
...

## 5. 가정사항
...
```

**경로**: `/output/logs/dependency_graph_[딜명].json`

```json
{
  "deal_id": "...",
  "generated_at": "...",
  "clauses": [...],
  "edges": [
    {
      "from": "c006",
      "to": "c007",

      "strength": "STRONG",

  "hub_clauses": [

| 조항 | 경로 | 영향 내용 | 위험 수준 |

## 변경 불필요 확인 조항

```

## DD 연계 모드

`step_dd_[딜명].json` 파일이 존재할 경우:

```
DD 이슈 목록 로드
→ 각 이슈에 대응하는 계약 조항 매핑
→ DD Critical 이슈 ↔ 계약 조항 의존관계 교차 분석
→ "DD 위험 + 계약 조항 취약점 중첩 구간" 강조 표시
```

출력에 추가 섹션:
```markdown
## 6. DD 이슈-조항 연계 위험
| DD 이슈 (심각도) | 관련 조항 | 의존관계 강도 | 복합 위험 수준 |
```

---

## 복수 계약서 모드

복수의 계약서가 입력될 경우 계약서 간 교차 분석을 수행한다.

```
[SPA] 제1조 "매매대금" ↔ [SHA] 제5조 "가치평가기준" 충돌 탐지
[PPA] 제8조 "완공일" ↔ [대출약정] 제12조 "인출선행조건" 불일치 탐지
```

출력에 추가:
```markdown
## 계약서 간 충돌·불일치 조항
| 계약서 A 조항 | 계약서 B 조항 | 충돌 내용 | 조정 필요 여부 |
```

---

## 오케스트레이터 연계

오케스트레이터(CLAUDE.md)가 이 에이전트를 호출할 때 전달하는 파라미터:

```yaml
agent: contract-dependency-agent
inputs:
  contract_file: /docs/[계약서파일]
  mode: full                          # full | hub-only | impact:[조항번호]
  deal_name: "[딜명]"
  scenario: "제6조 이자율 LIBOR→SOFR" # impact 모드 시만 사용
  dd_json: /output/logs/step_dd_[딜명].json  # 선택
```

## 에스컬레이션 기준

| 조건 | 처리 |
|------|------|
| 조항 파싱 실패 (인식 불가 포맷) | 파트너 에스컬레이션 + 수동 파싱 요청 |
| 의존관계 탐지율 50% 미만 | 재시도 2회 → 에스컬레이션 |
| 복수 계약서 간 Critical 충돌 발견 | 즉시 파트너 에스컬레이션 |

---

## 성공 기준

| 항목 | 기준 |
|------|------|
| 조항 분류 커버리지 | 전체 조항 100% |
| 명시적 교차참조 탐지 | 누락 0건 |
| 허브 조항 식별 | 상위 5개 이상 |
| 영향 분석 (impact 모드) | 2hop 이내 전수 분석, Critical 누락 0건 |
| 보고서 구조 | Executive Summary 포함, 결론 우선 구조 |
